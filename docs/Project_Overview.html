ML Fault Detection & Self-Healing in Telecom Networks

Technical Overview — Simulation, Machine Learning, and MAPE-K Evaluation

1. Purpose

This project implements an end-to-end pipeline for proactive RAN fault detection and MAPE-K-guided self-healing in dense HetNet mobile networks.

Research question: Can machine-learning-based proactive fault detection reduce Mean Time to Recovery (MTTR) and improve network availability compared to conventional threshold-based reactive monitoring?

The pipeline combines NS-3 network simulation, ML classifiers (Random Forest, LSTM, SVM), and a MAPE-K autonomic evaluation loop. Results are produced from observed simulation outputs — metric blending toward draft tables is disabled by default.

2. Real-World Operational Context

This is a simulation study that imitates operational scenarios common in Nigerian mobile networks (e.g. MTN, Airtel). It is not a live operator network integration.

3. System Architecture

NS-3 HetNet Simulation  →  KPI CSV Dataset  →  ML Training  →  MAPE-K Evaluation
                                                              →  MTTR + Availability

MAPE-K loop: Monitor (KPI window) → Analyse (ML, confidence ≥ 0.70) → Plan (remediation policy) → Execute (recovery time).

8 KPIs per cell per second: RSRP, SINR, PRB utilisation, DL/UL throughput, packet loss, handover success rate, latency.

7. Machine Learning Pipeline

  • 10-second sliding windows, stride 1, per cell
  • 48 tabular features + LSTM sequences
  • 70 / 15 / 15 % stratified split; SMOTE on train only
  • Models: Random Forest, LSTM, SVM
  • Output: reports/ml_metrics.json

11. Limitations

  • 280 UE stability default (500 is design target)
  • NR requires long runtime
  • Some Ch. 3 figures are schematic
